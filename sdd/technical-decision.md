# Technical Decision

## Status

Accepted

## Decision Type

stack, api-style, library

## Context

Project: vision-serving-fastapi
Problem: Serve a computer vision model via HTTP API with measurable throughput and latency
Portfolio program: applied-computer-vision
Public signal: FastAPI + Prometheus + benchmark infrastructure proficiency
Benchmark: throughput_rps, p95_latency_ms

## Selected Option

Selected: FastAPI over REST with Prometheus metrics and httpx-based benchmark

Reason:
FastAPI is the most widely adopted Python framework for ML model serving with native async support, OpenAPI docs, and TestClient. Prometheus is the standard for production metrics. httpx is the simplest way to run concurrent HTTP benchmarks without external dependencies.

## Decision Brain Fields

- Stack profile: fastapi-backend
- API style: rest-http
- Messaging: none
- Cloud mode: none
- Database/runtime: Uvicorn ASGI server
- Library policy: Minimal surface — FastAPI, Prometheus client, httpx, numpy. No ORM, no queue, no cloud SDK.

## Engineering Principles

Coupling boundary:
Domain types (InferenceRequest, InferenceResponse, BenchmarkResult) must not depend on FastAPI, Prometheus, or HTTP.

SOLID application:
- SRP: domain.py has pure data; app.py has HTTP concerns; model.py has inference; benchmark.py has load testing
- OCP: MockCVModel can be subclassed for real ONNX inference without changing routes
- LSP: Any model implementing predict(image) -> (class_id, name, confidence) is substitutable
- ISP: Small dataclasses with only the fields needed
- DIP: app.py imports domain types and model concretely — acceptable for a monolith

Simplicity:
- KISS: Mock model with random sleep; no image preprocessing pipeline
- YAGNI: No model versioning, A/B testing, request queueing, or caching
- DRY: Single predict path; no duplicated business logic

Testability evidence:
- Domain dataclasses tested without any server
- App routes tested with FastAPI TestClient (no real HTTP)
- Benchmark runs via subprocess or inline

## Rejected Options

| Option | Why rejected |
|---|---|
| ONNX Runtime as strict dependency | No real ONNX model; mock model uses numpy + random sleep |
| gRPC | REST is simpler for CV inference demo; gRPC adds protobuf compilation without benchmark benefit |
| Celery/background tasks | Synchronous inference is sufficient for the benchmark claim |
| Redis caching | Mock model latency is 10-50ms — caching adds no value |

## Benchmark Impact

Expected impact: ~50-100 req/s throughput, ~50-200ms p95 latency for a mock model with 10-50ms sleep.

Validation command:
```powershell
python -m vision_serving benchmark
```

## Operational Cost

- Docker services added: none (single container)
- Local demo complexity: low
- Failure case required: no

## Follow-up

If benchmark fails to produce measurable results, increase concurrency or reduce mock latency range.
